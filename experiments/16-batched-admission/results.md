## 1. The window against the rate of proofs

50 nodes, 8 peers each, one-way link latency uniform in 20 to 100 ms, the arrive timeout 500 ms, 12 s slots built by a proposer that rotates through the nodes, gas limit 400000000, profile `eip-8141`. From 12 s to 96 s users send self-paying frame transactions, each from a sender of its own, to random nodes, and each carries a proof under one key shared by all of them, which a node verifies before its pool sees the transaction: one at a time on arrival when the window is 0, and otherwise held from the first arrival of a batch until the window closes and verified as one batch, on one core whose time delays the admission. A proof costs 584.5 microseconds alone and a batch what Commonware measured for Pari proofs on one thread, interpolated between the sizes it measured (`sim/emem_sim/batch.py`). The run lasts 120 s. Rows pool 3 runs, seeds 1, 2, 3, each with its own topology and arrivals.

Rate is proofs a second under the key, network-wide, as asked; a user whose last transaction has not landed does not send another, so slightly fewer are sent. Batch is the mean number of proofs a node verified together. Verification is in microseconds a proof, and as a share of verifying each alone; a node's load is the milliseconds of verification a node spends a second while proofs arrive. Reach is the time from sending until 45 of the 50 nodes hold the transaction, and delay until a block includes it, in seconds.

## 3. Proofs that fail

Section 1's network at 100 proofs a second, with a sender of invalid proofs that hands each one, from a fresh sender, to every node at once. A node refuses it after verifying its proof, so it is never relayed and pays nothing, and in a batch it fails the batch, which the node bisects down to the proofs that fail (`sim/emem_sim/batch.py`). Checks are batch verifications a batch, bisection included. Verification is per valid proof, the invalid proofs' cost included, and its share is against verifying every valid proof alone with no invalid ones; a node's load is the mean, and the busiest node's, in milliseconds a second while proofs arrive.
